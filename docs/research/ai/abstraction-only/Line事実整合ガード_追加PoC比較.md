# Line事実整合ガード 追加PoC比較

## 結論

後続PoCの事実整合ガード候補として `combined_v1` を採用する。これは、決定的な静的検出と、レビュー済みのLine/Entry意味タグをRubyで照合する方式である。リアルタイムLLMは使用しない。

必須回帰ペアの E033 / L102 と E024 / L077 はどちらも除外できた。6カテゴリ12対の追加テストでは、致命的不整合の見逃し0件、適合ペアの誤除外0件だった。同一入力を再実行した除外理由も一致した。

この結果は静的ルールの本番採用を確定するものではない。追加テストは各カテゴリ1組の不適合・適合ペアであり、実運用語彙に対する再現率と誤除外率は本番データで継続監視する。

## 検証条件

- 実行日: 2026-08-13
- 元データ: 初回PoCの合成日記36件、Line 120件（Approved 96件）
- 追加ペア: 12件（数量、人物、物、出来事、場所・時刻、強い因果を各2件）
- ルール: `grounding-guard-v1`
- 属性: `grounding-attributes-v1`
- 外部API: 0呼び出し、0円
- 元の日記・Line本文: 変更なし

追加データは `data/grounding_guard_cases.yml`、事前属性と影版は `data/grounding_attributes.yml` に分離した。

## 比較結果

| 方式 | 正解率 | 致命的不整合の見逃し | 適合ペアの誤除外 | 判断 |
|---|---:|---:|---:|---|
| `shadow_line` | 91.67% | 1 | 0 | 箱を汎用化すると物の不整合を検出できず、単独採用しない |
| `reviewed_attributes` | 66.67% | 4 | 0 | 属性未登録語彙を見逃すため、単独採用しない |
| `static_detection` | 100% | 0 | 0 | 回帰ペアを満たすが、数量の意味役割までは表現しにくい |
| `combined_v1` | 100% | 0 | 0 | 静的検出を属性で補強でき、後続候補として採用 |

`combined_v1` は全6カテゴリの不適合ケースを各1/1件検出した。E032 / L102では「完了した三つ」と「始めなかった一つ」をレビュー属性で対応づけ、E020 / L077では箱を保持している事実を対応づけたため、どちらも過剰除外しなかった。

36件それぞれにApproved 96 Lineを与えてガードした。

| 指標 | 結果 |
|---|---:|
| ガード前候補数 | 各96件 |
| ガード後の最小 / 中央 / 最大 | 72 / 72 / 80件 |
| 除外判定 | 823件 |
| 空集合 | 0 / 36件 |
| 空集合によるSILENCE | 0% |
| 実行時間 | 97.621ms |

候補不足は起きていない。ここでの823件は正解ラベルではなく、具体的事実が対応しないため後段へ渡さない判定数である。誤除外の品質判断は12対の回帰データと、後続のBlind選択評価を分けて扱う。

## ルール

ガード対象は次の6カテゴリである。

1. 数量
2. 具体人物
3. 特定物
4. 特定出来事
5. 場所・時刻
6. 強い因果

静的検出では高確度の日本語パターンを意味トークンへ変換する。レビュー属性では、たとえば `three_completed`、`one_unstarted`、`box`、`store_closed` のように、Lineの要件とEntryの根拠を同じ語彙で記録する。Line側の要件がEntry側の根拠に含まれない場合、`category:missing:value` 形式の理由で除外する。

「少し遠い」「比喩的である」ことだけでは除外しない。このガードは事実の有無だけを扱い、obserbing distanceの品質判断は後続選択評価へ残す。

## 適用順

本番候補の適用順は次の通りとする。

1. Lineの公開状態
2. 再利用制約
3. 直近利用制約
4. 禁止Line
5. 事実整合ガード `combined_v1`
6. 選択方式

ガード後に候補が空なら、技術エラーではなく意味的な `SILENCE` として記録する。

## 再現方法

`poc/ai_line_selection` で実行する。

```powershell
bundle exec ruby bin\ai_line_selection plan-grounding-guard
bundle exec ruby bin\ai_line_selection compare-grounding-guard
bundle exec rake test
```

結果ディレクトリには `summary.json`、候補ID別の `case_results.jsonl`、全件適用時の `population_exclusions.jsonl` が出力される。結果ディレクトリはGit管理外である。

## 版管理方針

- Ruby判定規則を変えた場合は `grounding-guard-v2` のようにルール版を上げる。
- Line/Entryの意味タグを変えた場合は `grounding-attributes-v2` のように属性版を上げる。
- 回帰ペアは削除せず、誤選択が見つかるたびに別IDで追加する。
- 除外ログにはEntry ID、Line ID、ルール版、属性版、理由を必ず残す。
- 元のLineを汎用化する場合も上書きせず、影版として評価してから公開Line改訂の別工程へ渡す。
